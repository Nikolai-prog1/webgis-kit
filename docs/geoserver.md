# GeoServer

Use ASCII resource names without spaces; keep localized titles in config. A workspace per application helps organize layers and styles. Configure its relative proxy URL in `services`, then set `source.service` and `source.layers`. Unqualified layer names gain the workspace; style names are sent verbatim. A separate `labelStyle` overlay can draw labels above the base style.

Set `services.main.url` to the base GeoServer URL and `workspace` to the desired workspace. Every WMS operation (map, identify, capabilities and generated legends) then uses `{url}/{workspace}/wms`; WFS feature/schema requests use `{url}/{workspace}/wfs`. Already scoped URLs are accepted without duplicating the workspace. Omitting `workspace` explicitly selects global services. Workspace endpoints prevent global styles with the same name from shadowing an application's styles and scope ordinary dataset layers.

GeoServer can still advertise global layer groups in workspace capabilities; namespace filtering does not remove them. Use the catalog's explicit `include`/`exclude` filters when only an application's datasets should appear. The full demo allowlists the three seeded layer names, both qualified and unqualified. This avoids guessing group ownership or requiring REST credentials; see [GeoServer's global-group behavior](https://github.com/geoserver/geoserver/wiki/GSIP-73).

WMS draws images. WFS provides search, filters and attributes, so rendering success does not prove query permission or schema correctness. Configure `query` when the WFS type differs. WFS requests use `srsName=EPSG:4326` and longitude/latitude GeoJSON, including geographic BBOX values with an explicit CRS. The client projects geometries to the view CRS; Web Mercator display clamps latitudes to its supported range before transformation, so polar features cannot break a page or filter. CQL GET requests retain escaped literals/identifiers, limits, offsets and sorting. Tables without a stable primary key may reject natural-order paging; the adapter retries explicit sorting, but publishing a primary key is preferable.

Configure backend read permissions, CORS or a same-origin production proxy. Keep targets/credentials outside tracked config. Check the server's proxy base URL when generated legend URLs point to a backend hostname. Large datasets usually work best as WMS plus limited WFS queries. See [QGIS recipe](recipes/qgis-to-geoserver.md), [proxy guide](recipes/proxy-and-cors.md) and the optional local container example.
